# Instructions for Claude Code: Build a Modern Shared Shopping List & Recipe App

## 1. Product Vision

Build a mobile app that allows households to share shopping lists in real time. The app must support both authenticated users and guests who access lists via secure share links without needing to log in.

The app should make it easy to:

* Create and share shopping lists within a household
* Add, edit, check off, and remove items
* Share lists via secure links (no login required for guests)
* Add items from images (handwritten lists, screenshots, recipes)
* Add items from recipe URLs
* Automatically categorize items (e.g., produce, dairy, frozen, pantry)
* Correct spelling and suggest normalized item names
* Sort categories based on store layout
* Provide a modern, intuitive, and fast user experience

The app is initially built for iOS but should be architected for future Android support.

## 2. Recommended Tech Stack

### Frontend

* React Native with Expo
* TypeScript
* Expo Router for navigation
* Zustand or React Query for state management
* React Hook Form + Zod for forms and validation
* NativeWind (or similar) for styling

### Backend

Use Supabase:

* PostgreSQL database
* Supabase Auth
* Row Level Security (RLS)
* Supabase Realtime
* Supabase Storage for images
* Edge Functions for secure logic and AI integration

### AI Features

All AI calls must go through backend/Edge Functions.

AI should support:

* Extracting items from images
* Extracting ingredients from recipe URLs
* Categorization
* Name normalization and spell correction
* Suggesting quantity/unit when possible

## 3.1 Localization (i18n) Requirements

The app must support both Swedish and English.

Requirements:

* All user-facing text must use a localization system (no hardcoded strings)
* Default language should be based on device locale
* User must be able to switch language manually in settings
* Support at minimum:

  * Swedish (sv)
  * English (en)
* Use a standard i18n library (e.g., i18next or expo-localization)
* Store translations in structured files (e.g., JSON)

Example structure:

```
/locales/
  en.json
  sv.json
```

* Keys must be stable and descriptive (e.g., `list.add_item`, `error.invalid_link`)
* Backend/AI responses should also respect language where possible
* Category names should be localized but mapped to a canonical internal identifier

1. Adding items must be extremely fast.

## 4. User Roles

### 4.1 Authenticated User

Can:

* Create households
* Create lists
* Invite members
* Create share links
* Manage lists and items
* Configure category sorting

### 4.2 Household Member

Can:

* View lists
* Add/edit/check/remove items
* Use AI features (if enabled)

### 4.3 Guest via Share Link

No login required.

Can (depending on permission):

* View list
* Add items
* Check items
* Remove items

Cannot:

* Access other lists
* See members
* Change settings
* Create links

* Secure token

#### QR Code Support

The app must support generating and displaying a QR code for each share link.

Requirements:

* When a share link is created, the user can also view a QR code representing the link
* QR code should encode the full share URL
* QR code must be scannable by standard camera apps
* Include a dedicated UI for displaying the QR code (e.g., modal or share screen)
* Allow easy sharing of QR code (e.g., screenshot or native share)
* Ensure QR codes respect link permissions and expiration

Guest flow via QR:

1. User scans QR code
2. Opens app (or web fallback if app not installed)
3. Link is validated server-side
4. User sees list with correct permissions

Optional (nice-to-have for later):

* Deep linking to open directly in app
* Branded QR code styling
